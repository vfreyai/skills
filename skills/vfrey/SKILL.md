# vfrey

**First, always: for any video request, find the project (next section) before anything else. No `vfrey.json` here or in a folder above means your whole first reply is the project offer (step 2): write no files, make no `videos/` or `scripts/` folder, do not start the video, ask no other question, and wait for the yes.** vfrey is self-contained: use only `npx vfrey` commands and the files next to this file. Do not use or look for any other installed video skill or tool (HyperFrames, HeyGen, media-use, Remotion skills, an "explainer" or other workflow) unless the person names it; if a vfrey command fails, relay its `Fix:` line. The person asks in plain language; you run `npx vfrey`. Videos live in a project folder (it has a `vfrey.json`). **Research needs no project:** `research` and `creators` work in any folder, so never `init` or create a project for them (outside one, run `npx @vfrey/vfrey research ...`). `ingest` is the older name for `research` and still works. **Setup:** needs Node 22.13 or newer and ffmpeg; nothing else to install first, because every command runs through npx. Inside a vfrey project `npx vfrey` runs the project's own copy; outside one use `npx @vfrey/vfrey` (never bare `npx vfrey` there: that npm name is not vfrey's). If `npx` is missing or Node is older, say so and ask the person to install Node; never install it for them. `npx vfrey doctor` checks the machine and prints a `Fix:` line for anything missing. How each coding agent loads this skill, and what differs between them: `agents.md` next to this file.

## Find the project

1. Look for `vfrey.json` in this folder or any folder above. Found: work there (`cd` to it). Read its `AGENTS.md` if you have not. Data safety, in one plain sentence to the person when you first create or open a project: Everything vfrey makes lives in this folder; keep it in iCloud Drive, Dropbox, or under Time Machine so a lost or deleted folder is not lost work.
2. Not in a project and they want a video (**this is your first and only action; do nothing else until the yes**): say there is no vfrey project here and offer to create one with `npm create vfrey@latest <name>`; ask where it should live (suggest `./vfrey`, or a name for their channel) and wait for their yes. Never run it unasked. Then `npm create vfrey@latest <dir>` (`npx create-vfrey@latest <dir>` is the same) and `cd <dir>`. If they want the current folder: `npx @vfrey/vfrey init`. For videos, never run `npx vfrey` or `npm i vfrey` outside a project. Both are safe to repeat.
3. They have old videos in `~/.vfrey`: `npx vfrey init --from ~/.vfrey` imports them (the source is not changed).
4. Look in `.vfrey/requests/`: each file is a request the person sent from the dashboard. Handle it, then delete it (`captions.md`). A request that holds a remix file (it starts `# Remix:`) means: read the post in it, work out why it worked (hook, beats, length, what made people watch or comment), then write your own script and scene, and pass `--from <the post link in the brief>` when you make the video (**Make a video**, step 5). 
5. Skill not loaded in this agent: `npx @vfrey/vfrey@latest skill install --agent <claude|codex|grok|cursor|gemini|all>` (inside a project `npx vfrey skill install` is fine) (restart Claude Code and Cursor; Gemini: `/skills reload`). **If `npx vfrey` prints an npm `404` for `vfrey` (or `vfrey@*`): this project's packages did not install, so npm looked up another package with that name. Run `npm install` in the project folder, then try again. `npx @vfrey/vfrey doctor` names what is missing.**

## Series kit

**Before you write a script, a scene, an image prompt or a remix for a series, run `npx vfrey series kit <series>` and follow it.** A new project already has its first series, `desk`; `npx vfrey series list` prints the ids (`desk snapshot` too). It starts with a Settings block (the engine, shape and size, frame rate, voice, language and caption position the person set in the desk): use those, and pass no flag that changes them unless the person asks for a one-off (`--override`). Then it prints the series' guidelines, style line, characters (with sheet paths), references and brand summary, and leaves a read receipt; a run made without one in the last 24 hours gets a `kit.unread` warning. When a video style is set (the kit's `Style:` line), its skill is the look of every scene and the starter `style.md` line does not apply to scenes; when none is set, the starter line is only an example, and a `style.md` the person wrote is reused word for word in every stand-alone image prompt. Pass the character sheets as reference images when your image tool supports it (`npx vfrey series kit <series> --paths` lists them). Never change the kit unless the person asks. A new series' guidelines and starter style line are examples: an example-only or blank kit is normal, not unfinished, so follow it as written and do not ask the person to fill it in. To add to it: `series kit add <series> <file> --as reference|character:<name> --source own|generated:<tool>|licensed:<where>`; `series kit check <series>` finds problems. Details: `series.md` next to this file. **Video styles:** each is its own skill, `vfrey-style-<name>` (`npx vfrey styles list`); when the kit settings or the tick show a `Style:`, load that skill before you write scenes (details in `styles.md`).

Never start the dashboard any other way. "my videos": `npx vfrey videos` (newest first, with paths); "my other projects": `npx vfrey projects`. "Export it for TikTok/Reels/Shorts/X", "give me the file", "an SRT": `npx vfrey export <run id|title|path> [--preset tiktok|reels|shorts|x|master|custom] [--resolution 1080|1440|source] [--fps source|30|60] [--quality standard|high | --mbps N] [--codec h264|h265] [--no-srt] [--vtt] [--cover] [--out DIR] [--name PATTERN] [--json]`: the finished video encoded for that platform (never larger or faster than it was made, no watermark) with its SRT, named `{series}_{title}_{platform}_{date}`, in `exports/`. Local files only; nothing is uploaded. A Render video's captions are part of its picture, so there is no clean copy.
- "what should I make", "trending in X": `npx vfrey topics --niche X` (ids: `topics niches`; both are free: 0 credits, an account is needed, and reads count toward the monthly topics limit. Only `topics request`, a new niche, costs 25 credits: it prints the price and stops until you pass `--yes` after the person agrees; `--quote` shows the price and spends nothing); cite the evidence, then `tick --now --about "<title>"`. **Research with vfrey** (creators, KOLs, influencers, trends, competitors, one creator, a topic across platforms): use the `vfrey-research` skill if it is installed; otherwise follow `research.md` next to this file. Outreach: draft with `npx vfrey mail draft` (free); NEVER approve or send unless the person says so for that specific draft. "remix this post", "make my own version of this", a post link that did well: `npx vfrey remix <post-url>` writes `briefs/remix-<slug>.md` (free; it reads the person's local research runs, then their account; `--transcript --yes` is a paid read, ask first). The file holds the post's numbers, caption and full transcript plus the rules, and no analysis: read it, work out why the post worked, then follow **Make a video** with `--from <post-url>` in step 5. "how did my videos do", "results": `npx vfrey results [--days 7|30|90|all] [--refresh] [--csv F]` (views, likes, comments, lift against their own usual, and "remixed from" with the source's lift; `--refresh` reads the platforms; a dash is unknown, never zero; TikTok may need `connect tiktok` again for `video.list`).
- "sign in", "my plan", "my credits": `npx vfrey login` (prints a link and a code to relay) or `npx vfrey whoami`. Team sync: `npx vfrey cloud link|push [--videos]|pull|status` (newest wins; the other copy is kept as `<file>.conflict-<time>`).
- **Free, no account:** the local CLI, rendering on this machine, local autopilot, the local dashboard, a series' RSS and YouTube channel feeds, and `research report` on run folders already made. **Needs sign-in, even at 0 credits:** `research`, `topics` (niches, stored topics) and `creators` (browse, alerts). **Costs credits (needs `login`):** a new topics niche 25 (`topics request`: price first, then `--yes`), creator lookup 3, an approved email 1, cloud render 10 per output minute (billed per started 15 s); failed calls and cache hits cost 0. Credits are prepaid, and a new account has its signup credits. Every paid feature works on every plan and credits are the only limit, except sending mail (a paid plan or a past top-up; drafting is free). Never say a feature is "in the Research plan", "Pro only" or "a Mail add-on". `credits_required` (`✗ Not enough credits`): say it needs N credits and they have M, and relay the `Fix:` line as printed. Payments are not open on vfrey.ai yet, so a top-up or plan cannot be bought until they are; say that, and that signup credits are what a new account has; `plan_required` (mail sending only): sending needs a paid plan or a top-up, at that URL. Relay URLs as printed; never pay or approve for them.
- "clip this stream", "work a clipping campaign", "Whop", "post clips for pay": use the `vfrey-clip` skill if it is installed; otherwise `npx vfrey clip --help`. Footage is fetched only when the campaign allows it (a channel it lists, or a file link it shares); the `vfrey-clip` skill does that, never by hand.
- Old machine data, update, engines: `npx vfrey desk snapshot --json`, `npx vfrey update`, `npx vfrey engine list`. A run with `status: awaiting_review` waits for the person (series review on): tell them, then `npx vfrey desk job approve|reject --id <id> [--reason T]`. `npx vfrey --help` and `npx vfrey <command> --help` list the rest. Planning a series or several videos from a channel brief with more than one theme, or setting up a second channel (one channel = one project, or one series with its own engine, shape and style): read `series.md` next to this file first.

## Make a video

You are the writer and the designer. vfrey has no model of its own; without your script the words are template filler, and without your scene the picture is a plain fallback. **Ask as few questions as possible: the project question (Find the project, step 2) is the only one for a clear request.** Do not offer a menu of angles, platforms or formats, and do not ask who builds it, whether to review a plan, or "anything else?". Choose the defaults yourself: a vertical 9:16 short (1080x1920, 30 fps), the angle you judge best for the request, the length they gave (else about 30 s), no review step, and you write and build everything with vfrey. Say what you chose in one line ("I'll make a vertical 9:16 short, about 30 s, on <angle>; tell me if you want something else") and carry on; ask more only when the request cannot be understood.

1. **Script.** Write `scripts/<idea>.json`: `{ "title", "hook", "lines": [...], "hashtags": [...] }` plus an optional `"captions"` (`"off"`, or `{ "position", "style" }`), `"thumbnail"` (`true`, or `{ "at", "title" }`) `"language"` (the lines' language code, such as `"ar"`; omitted, it is read from the text), `"voice"` (a voice name; `npx vfrey tick --voice NAME` beats it), `"lineGap"` (seconds of silence between spoken lines, 0 to 3; see `voice.md` "Pauses between lines"), `"credit"` (who made what the video reads or shows, such as a public post; added to the end of the description) and `"subject"` (the topic; it is only used when you leave out `--about`, so pass `--about` and skip it). `npx vfrey tick --script-template` prints one. 6 to 10 short spoken lines (4 to 30 allowed, at most 220 characters each; speech 6 to 180 s), hook first, title at most 100 characters, 1 to 8 hashtags starting with `#`. If they gave a length ("20 to 30 seconds"), pass `--duration 20-30` in step 5 and size the script by the pace in the `series kit` Settings block; time a draft before you trust an estimate (`voice.md` next to this file has the method, `npx vfrey voice sample <voice> --file lines.txt --language <code>`; `--file` is one spoken line per row, `--script` is the script JSON). A voice outside the range stops before the render and the Fix names how many words to cut or add. Be accurate and plain: no invented statistics, numbers, quotes or sources; leave out what you are not sure of. Use the topic's key words (the quality check rejects a script that never mentions its subject). **From a remix file (`briefs/remix-<slug>.md`):** you do the analysis. Read the post's data and transcript, say to yourself why it worked, keep that pattern (hook type, beats, length within 20%), not the words, and do not copy its lines. New angle, facts you checked, the person's voice, niche and brand (take them from the project). A bad file gets a `✗` line and a `Fix:` line; a rejected script prints its reason. Fix and rerun.
2. **Scene.** Always design a scene for the idea (scene init, design, `--frame` preview, then tick with `--scene`). Use the default template only if the person explicitly asks for a quick text-only video, and say so. Every idea gets its own picture ("what's the difference?", "3 facts", "how a mutex works" look different). There are no fixed templates: never reuse one scene for a new idea.
   - `npx vfrey scene init scenes/<idea> --script scripts/<idea>.json` writes a commented starter (`index.html`; `--engine remotion` writes `index.tsx`) with timing from your script; without `--script` its `timing.json` is a placeholder from a sample script. Replace it. Draw SVGs yourself and `<img>` them from the folder.
   - `index.html` renders with `vfrey-render` (or `hyperframes`), `index.tsx` with `remotion`; a mismatch stops with a `Fix:` line. For a series run, use the engine from `series kit` (its Settings block) and pass no `--engine`; for a quick video with no series, pass `--engine` with a scene. A scene whose root is laid out at another shape than the video is measured in the page before the render: `tick` rejects it (`scene.shape`) with a `Fix:` line: size the root 100% and lay out from `vfrey.frame` (HTML) or `useFrame()` (Remotion), or keep a fixed design and fit it with `vfrey.fitStage`. A scene that throws an uncaught error or loads a script that is not in its folder (a style's companion file such as `papercut.js`) is rejected the same way (`scene.page-error`), never rendered blank.
   - vfrey supplies in `DIR/vfrey/` (rewritten at render, do not edit): `timing.json`, `voice.wav`, `vfrey.js`, local `gsap.min.js`, `fonts/fonts.css` (Baloo 2 plus Noto faces for the scripts `captions.md` lists; Korean has no bundled face and uses a font already on the computer; Titan One, JetBrains Mono, Google Sans Flex, Playfair Display serif), `brand.json` and `brand.css` (the brand kit; `brand.md`), `assets/` (stick figures `stick-*.svg`, glyphs `glyph-*.svg`).
   - Timing: `vfrey.timing` (HTML) or `useTiming()` (Remotion): `durationSec`, `words[{i,text,start,end,line}]`, `lines[...]`, `beats[...]`, in seconds. `vfrey.frame` / `useFrame()` is the frame: `width`, `height`, `fps`, `aspect`, `orientation`, `vmin`, `safe`. The film is voice length plus 0.3 s, 9:16 at 1080x1920 and 30 fps unless the person asks for another shape (`--aspect 16:9`, `--size WxH`, `--fps 24|30|60`); lay out in fractions of the frame, never 1080 or 1920. Place the caption block with `top: var(--vf-caption-at); height: var(--vf-caption-h)` (HTML; `vfrey.captionBox`) or `useCaptionBox()` (Remotion): it follows `captions.position` from the script, else the series (`desk series update --caption-position`), else `vfrey.json` (`"captions": {"position"}`); `--vf-caption-top` and `--vf-caption-bottom` are fixed edges and do not follow it (`scenes/craft.md`).
   - HTML: `<link rel="stylesheet" href="vfrey/fonts/fonts.css">`, `<script src="vfrey/gsap.min.js">`, `<script src="vfrey/vfrey.js">`; `const tl = vfrey.timeline()` (the one paused GSAP timeline); `vfrey.captions("#el", {style})` (`box`, `color`, `underline`, `pop`, `plain`; also `size`, `color`, `highlight`, `highlightText` (the spoken word's colour on its box), `font`, `maxWords`, `align`; it follows the script's `captions` setting); `vfrey.at(t, fn)`, `vfrey.onWord(i, fn)`, `vfrey.onLine(i, fn)`, `vfrey.line(i)`. Everything visible must be a function of timeline time (no `Date.now`, no unseeded random).
   - Remotion: `import { useTiming, useScript, useTime, Captions, AtLine } from "@vfrey/scene"`; `export default function Scene()`.
   - **Never type the title (or any line of the script) into the scene.** Read it: `vfrey.script.title` (HTML) or `useScript().title` (Remotion); `vfrey.script` / `useScript()` also hold `hook` and `lines`. A language version (`--languages vi`) renders the one shared scene once per language, and each run's `script.title` is that language's. A title typed into the scene shows the same words in every language.
   - vfrey burns the `AI-GENERATED` label on top after render; nothing can hide it. The network is blocked while rendering (no CDNs). A scene folder is at most 50 MB. `npx vfrey scene edit scenes/<idea> [--script scripts/<idea>.json]` opens the Scene editor for the person. Its script panel shows the scene's own script (the last run that used the scene, else `scripts/<scene>.json`, else the `--script` file), never the example script; with none it says so and lets the person pick one. The editor's element ids stay out of your `index.html`.
   - **Read this when** (all files are next to this file; read the one that matches, not all of them):

     | When | Read |
     | --- | --- |
     | Other shapes and frame rates, covers (`--thumbnail`), videos up to 180 s, free voices on Linux | `formats.md` |
     | Captions on, off or moved, subtitles (SRT/VTT), other languages and right-to-left text | `captions.md` |
     | The person's brand kit (`brand.json`: colours, fonts, logo, caption look; read it first and design inside it) | `brand.md` |
     | The person's own logos and images (own, generated or licensed only; never hot-link or scrape; record each `source` in `assets.json`) | `captions.md` |
     | Before designing any scene (layout, type, safe areas, motion, pacing); GSAP recipes | `scenes/craft.md`, `scenes/motion.md` |
     | The person gives you their own photos or footage, or asks for a photo story, a slideshow or a "video from my pictures" (otherwise stay on the default engine and a designed scene; pass `--engine pictures` with a `media.json` next to the script) | `media.md` |
     | Two or three versions of one idea to compare (a hook, a title or a cover) | `variants.md` |
     | A music bed under the voice (own, licensed or generated music only, never from YouTube or TikTok; a licence does not stop a Content ID claim), the person's music folder (`npx vfrey music list`) | `music.md` |
     | Many videos planned in a spreadsheet (`npx vfrey plan import plan.csv`) | `series.md` |
     | A faster or slower voice (`--voice-speed`), pauses, sampling | `voice.md` |
     | The same idea in several languages (`--languages vi,es`; you write each translation) | `languages.md` |
   - Two worked examples are in `examples/` next to this file (`concurrency-vs-parallelism/`, `octopus-facts/`). Read one, then design for the idea in front of you; do not copy.
   - Preview: `npx vfrey render --scene scenes/<idea> --engine <engine from series kit> --script scripts/<idea>.json --frame 2.5 out.png` (silent, label on; always pass `--script`, or the sample script times the frame). Open it, fix the layout, check a second moment (`--frame 9`). Before a voice exists the frame is timed by an estimate (the `Timing:` line says so); every `render --scene` and every successful tick saves the voice-anchored timing it used into the scene's own `vfrey/timing.json` (a language version, `tick --languages`, into `vfrey/timing.<lang>.json`), so after the first full render re-check the frames at those beat times.
3. **Quality checks.** vfrey reviews every video before and after the render. Read the Checks list on the run page or `checks` in `npx vfrey tick --json`; each check has an id and a Fix line. Do the Fix; never work around a check. `remix.too_close` (a video made with `--from`) fails a script when over 15% of its five-word runs also appear in the source's transcript or caption; its Fix line names the phrases: rewrite those in your own words and rerun. Limits: spoken length 6-180 s; start from the measured pace of the voice that will speak: time your first draft with `npx vfrey voice sample <voice> --script <draft.json> --language <code>` and size the script by the pace it prints (the `series kit` Pace line shows that number from then on). Never size a script by a fixed words-a-second figure: the pace depends on the voice, the language, `lineGap` and full stops, and the measured pace is stored per voice and language, so read it from the kit's Pace line or a sample; until a sample has run, the kit's Pace line is an estimate and says so; rendered file the frame you asked for (default 1080x1920 at 30 fps), not black, not frozen. A dry run skips the after-render checks.
   - Quality failures (copy, pace, scene, frames) reject the job; vfrey re-renders once when a render can change the result. Otherwise fix the named problem and rerun.
   - Compliance failures (banned claims, missing disclosure, missing AI label) block the job and are never retried; nor is a rejection before the render (placeholder text, a repeat): `desk job retry` refuses them, so change the script and run `tick --script` again. A run killed mid-render is interrupted and a plain `tick` never finishes it, however long ago; `tick --resume <id>` does.
4. **Scene blocks.** Ready-made pieces (lower thirds, charts, code, chat cards, overlays, backgrounds, transitions) to restyle, not templates; one or two per short at most.
   - `npx vfrey scene blocks [--category X]` lists them; `npx vfrey scene add BLOCK scenes/<idea>` copies one into the scene and prints the snippet to paste into `#root`.
   - Time it with `vfrey.block("#block-<name>", t)` inside `vfrey.onLine` or `vfrey.at`; mount each block once per scene; HTML scenes only. Placement, fit modes and restyling are in `scenes/blocks.md`.
5. **Make it.** Run `npx vfrey tick --now --about "<subject>" --script scripts/<idea>.json --scene scenes/<idea> --series <id> [--duration 20-30] [--thumbnail] [--from <post-url>]`
   - `--about` is the subject (no feed is read; it runs as its own job); without it the default series reads the Federal Reserve feed: say so and ask once for a topic. Leave `--script` out only if they say to let vfrey write it, and then say the words are generic. Always pass `--scene` (without it tick uses `scenes/<script name>` when it exists, else says "default template" on stderr and renders plain text). `--from` is the post you remixed; the video and its publications record it, so Results can show "remixed from" and the source's lift.
   - **A series run:** pass no `--engine`, `--aspect`, `--size`, `--fps` or `--voice`: they are the person's desk settings (printed by `series kit`), and a flag that disagrees is refused with a `Fix:` line. Order: the series' setting, then the project's (dashboard Settings, or `aspect`/`size`/`fps` in `vfrey.json`), then the default (9:16 at 30 fps). **Only when the person asks for a one-off that differs** ("just this one in 16:9"), add the flag and `--override <field>` (engine, aspect, fps, voice, captions); the run records it. With several series pass `--series ID`; the report says when the series (not the flags) set the frame rate. **A quick video with no series:** the flags work as they always did; `--engine vfrey-render` is a fine choice.
   - **Again after a fix:** add `--rerender` to the same `tick` (with `--script` and `--scene`); without it the variation gate rejects the same hook and title as a repeat. It is a new run and the old one stays; `desk job retry` on a succeeded job and `desk job delete` are refused on purpose (their Fix line says so). Never set `--dry-run` for a real video: it renders nothing and writes an empty placeholder `.mp4` (the report says so). `render --subject` is only a silent, untracked preview. **Exit status:** A tick whose every job ended without a video (rejected, blocked or refused) exits 1, with the reason and a `Fix:` on the screen (and on stderr with `--json`). A tick that made at least one video exits 0, even with warnings: read the `Look at these warnings` lines before you say it is done. Do not treat exit 0 as "posted" either: a series that is not live only records a practice post.
6. **Tell them.** The summary is short: `✓ Video ready: <path> (<length>, <size>)` (quote the length and size), `Watch: <link>`, a `Not posted (<why>)` line when nothing was posted, and a `!` line for each warning (relay those in plain words before they post). Relay the readable video path in `videos/` and the `Watch:` link as they are, without hedging. With the dashboard running (the tick starts it unless `VFREY_NO_DASHBOARD=1` or `--no-dashboard`; `npx vfrey dashboard stop` stops it) `Watch:` is the live run page `http://127.0.0.1:<port>/runs/<id>`; with it off it is the command `npx vfrey open <id>`, which opens the run: say that, not a link. Only if `curl` to the link fails, run `npx vfrey open`. A `Tip:` line about the computer voice: tell the person and offer the install. For everything else (voice, settings, style, engine, scene, subtitles and transcript paths, hashtags, content credentials, the dashboard note) run the tick again with `--verbose`, or read `--json`; `<title>.srt` and `.vtt` sit next to the MP4. Say the scene is agent-written (or that it used the default template). `--json` has `{processed, jobs:[{id, series, status, mp4, transcript, durationSec, frame, thumbnail, publish, engage, runUrl, scene, engine}]}`. Nothing made: the summary says why (`not due`, `paused`, `job <id> in progress` with its `npx vfrey desk job cancel --id <id>` fix). Never move or rename videos by hand; vfrey tracks the paths.
   - Voice is on by default. Until the person installs a natural voice the system voice speaks and sounds robotic: **when a run summary has `Tip: this is a computer voice. For a natural one: npx vfrey voice install ...` (or `... --language vi`), tell the person and offer to run it** (a public model into `~/.vfrey/models/`: the download is about 92 MB for English (about 237 MB on disk) and about 401 MB for 31 other languages (about 443 MB on disk); it never runs on its own). Offer the free local voice first, and ElevenLabs (their own key) only after that. **Never pick or suggest sending script text to a paid voice unless that key is already set**, and never ask for the key in chat. Voices, languages, sampling and pace: `voice.md` next to this file. To check a dashboard link is live: `curl -s -o /dev/null -w "%{http_code}" <url>` expects `200`.

## Rules

- **Engines.** The person chooses; `npx vfrey engine list` shows ready or unavailable with reasons, `npx vfrey engine use <id>` sets the machine default (Render, `vfrey-render`, until then). For a series run the engine is the series' (shown in `series kit`): pass no `--engine`; a one-off on another engine is `--engine remotion|vfrey-render|hyperframes|pictures|agent` with `--override engine`. **When the series engine is Made by your agent (`agent`), you make the whole MP4 yourself: read `agent-video.md` next to this file.** A chosen engine never falls back: a failed one ends the run with a `Fix:` line naming another; relay it, never quietly switch.
